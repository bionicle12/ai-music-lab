# Карта по времени

[← Документация](README.md) · [English](../timeline.md)

**Вопрос, на который отвечает вкладка:** какие секунды трека несут отпечаток?

Глобальный score не говорит, что чинить. Скользящее окно по тому же треку показывает, какие
участки его дают.

## В интерфейсе

Откройте вкладку **Карта по времени** после анализа, выберите длину окна и шаг, нажмите
**Построить карту**. `lofcz` прогоняется по последовательным окнам поверх уже сделанного
запуска.

Новый run при этом не создаётся. Карта сохраняется как телеметрия существующей версии в
`data/runs/<run_id>/telemetry/lofcz-timeline/`, поэтому её можно построить и для старого
запуска, не трогая его запись в истории. Клик по кривой перематывает плеер.

Если у запуска есть телеметрия FST, поверх накладывается его `fusion gate` на отдельной правой
оси. Это сырой сигнал модели, а не вероятность «AI» по сегменту, и он намеренно не
переименовывается: upstream не публикует надёжного соответствия классов Stage-1 меткам
`Real`/`Fake`.

## Из командной строки

```powershell
conda run -n ai-music-lofcz python adapters\lofcz_cli.py --upstream ..\ai-music-detector --model models\lofcz\ai_music_detector.onnx --audio "path\to\track.mp3" --mode timeline --window-seconds 15 --hop-seconds 5 --json-output artifacts\timeline.json --npz-output artifacts\timeline.npz
```

В JSON попадают сводка и самые «горячие» окна. В NPZ — полные массивы:

| Массив | Что это |
| --- | --- |
| `window_start_seconds` | Начало каждого окна |
| `window_end_seconds` | Конец каждого окна |
| `window_center_seconds` | Центр, удобен как ось X при построении |
| `probability` | Выход модели для этого окна |
| `mean_residue_db` | Сырое измерение сигнала, без участия модели |
| `stft_frames_per_window` | Сколько кадров усреднялось |
| `fakeprint_by_window` | Матрица формы `окна × 3585` |

## Ограничение, которое важно держать в голове

Модель обучалась на усреднении по всему треку. Поэтому оконные значения — это
**относительная карта внутри одного трека**, а не калиброванная вероятность на секунду. Отсюда
два правила:

- Сравнивайте окна с другими окнами *того же трека*. Сравнивать значение окна с глобальным
  score другого трека бессмысленно.
- Чем короче окно, тем меньше STFT-кадров усредняется и тем шумнее оценка. Окно 15 секунд с
  шагом 5 — разумная отправная точка.

`mean_residue_db` — встроенная проверка. Это сырое измерение без модели в тракте, поэтому если
оно вообще не коррелирует с кривой модели, к оконным числам стоит относиться с большей
осторожностью, чем обычно.
