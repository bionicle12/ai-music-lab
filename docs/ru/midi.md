# Аудио → MIDI

[← Документация](README.md) · [English](../midi.md)

**Вопрос, на который отвечает вкладка:** какие там на самом деле ноты, чтобы переиграть их не
генератором?

Транскрипция работает на [muscriptor](https://github.com/muscriptor/muscriptor) —
мультиинструментальной модели audio-to-MIDI от Kyutai и Mirelo. Работает локально, в своей
conda-среде, на вашей видеокарте.

## Что должно сойтись, прежде чем это заработает

Четыре пункта. Чек-лист в **настройках** (шестерёнка рядом с названием) показывает, какие из них
не сошлись, а первая непройденная строка говорит, что с этим делать.

### 1. Клон и среда

muscriptor — pip-пакет, но клонируется соседом и ставится в editable-режиме: тогда `git pull`
обновляет тот код, который реально исполняется, а ради этого проект и отслеживается — его до сих
пор чинят.

```powershell
cd ..
git clone https://github.com/muscriptor/muscriptor.git
cd ai-music-lab
conda create -n ai-music-muscriptor python=3.11 -y
conda run -n ai-music-muscriptor python -m pip install torch --index-url https://download.pytorch.org/whl/cu128
conda run -n ai-music-muscriptor python -m pip install -e ..\muscriptor
```

Проверьте, что установка легла на клон, а не на копию с PyPI — иначе pull клона ни на что не
влияет:

```powershell
conda run -n ai-music-muscriptor python -c "import muscriptor; print(muscriptor.__file__)"
```

Путь должен быть внутри `..\muscriptor`. Кнопка **Проверить окружение** в настройках делает то же
утверждение и красит строку *Проверка пакета* красным, если это не так.

### 2. Принять лицензию на Hugging Face

Веса gated. Откройте страницу того размера, которым собираетесь пользоваться —
[small](https://huggingface.co/MuScriptor/muscriptor-small),
[medium](https://huggingface.co/MuScriptor/muscriptor-medium),
[large](https://huggingface.co/MuScriptor/muscriptor-large) — и примите CC BY-NC 4.0. Доступ
выдаётся автоматически.

### 3. Токен

Создайте на [huggingface.co/settings/tokens](https://huggingface.co/settings/tokens). Токена типа
**Read** достаточно.

Если вместо этого создать **fine-grained**, до gated-репозиториев он не достанет, пока не отмечен
пункт *Read access to contents of all public gated repos you can access*. Эта единственная
галочка — самая частая причина, по которой загрузка падает с ошибкой прав при живом токене.

Два места, куда его положить:

| Куда | Следствие |
| --- | --- |
| Панель настроек | Лежит в `data/settings.json` открытым текстом. Файл в .gitignore, но локальный и без защиты сверх вашей учётной записи. |
| `HF_TOKEN` в окружении | На диск ничего не пишется. Имеет приоритет над сохранённым. |

В любом случае токен передаётся процессу muscriptor переменной окружения и больше никуда:
никогда аргументом командной строки (они видны всему, что умеет смотреть список процессов),
никогда в историю запусков, панель технических данных или лог. Панель показывает только
последние четыре символа.

### 4. Скачать веса

| Вариант | Параметров | Загрузка |
| --- | ---: | ---: |
| `small` | 103M | ~0.4 ГБ |
| `medium` | 307M | ~1.2 ГБ |
| `large` | 1.4B | ~5.6 ГБ |

Выберите в настройках и нажмите **Скачать веса**. Они лягут в `models/muscriptor-cache/`
(приложение направляет туда `HF_HOME`), а не на системный диск.

После загрузки адаптер сразу перечитывает веса с `HF_HUB_OFFLINE=1`. Зелёная галочка тогда
означает, что кэш действительно разрешается, а не просто что появился какой-то файл.

Приложение выполняет одну задачу за раз, поэтому загрузка занимает весь интерфейс до конца.

## Транскрипция

Три источника: стем, присланный из вкладки **Слои**, аудио текущего запуска или загруженный файл.

**Подавайте стемы.** Полифоническая транскрипция плотного микса не решена, и разница между
басовым стемом и полным треком, из которого он взят, — это разница между результатом, который
стоит править, и тем, который стоит удалить. Ровно для этого кнопка **Отправить в MIDI** в
«Слоях»: измерьте стемы, кликните нужную строку, отправьте её сразу сюда.

`Только эти инструменты` фильтрует выход — `drums, acoustic_piano` и так далее, через запятую.
Пусто — оставить всё, что muscriptor услышит.

Декодирование **жадное**, без сэмплирования и температуры, поэтому одно и то же аудио с теми же
настройками даёт тот же MIDI. Каждый прогон пишет рядом с `.mid` JSON с чекпоинтом, параметрами
декодирования и версией muscriptor, чтобы старая транскрипция осталась интерпретируемой после
обновления.

Результат кладётся в `output/midi/<метка времени>-<имя>.mid`, а не в кэш Gradio: тот чистится
раз в сутки, а файл, который вы собираетесь открыть в DAW, должен пережить этот день.

## Как проверить результат, не открывая DAW

Готовый файл сразу читается обратно и показывается двумя способами.

**Пиано-ролл**, по цвету на дорожку инструмента, на той же временной оси, что и все остальные
графики приложения — поэтому клик по нему перематывает плеер, а playhead идёт по нему во время
воспроизведения. Именно здесь видно, попадают ли ноты туда же, куда аудио.

**Плеер превью**, синтезированный из нот простыми синусами и шумом. Это не сведение и не
пытается им быть: собственная аурализация muscriptor требует бинарника fluidsynth — лишняя
системная зависимость ради того, чья единственная задача ответить «услышал ли он то, что надо».
Барабаны выходят тремя грубыми группами: бочка, малый, всё металлическое.

Чтение файла обратно — это ещё и последняя проверка, что прогон действительно удался: `.mid`,
который не разбирается, означает провал, что бы ни говорил payload.

## Что вы получите, а что нет

Высоту, тайминг и отдельную дорожку на каждый распознанный инструмент. Не артикуляцию: легато,
стаккато, штрихи, глиссандо и бенды в MIDI не попадают и вписываются руками. Гитара приходит
нотами без информации о ладах и струнах. Суб-бас ниже примерно 40 Гц часто уезжает на октаву, а у
сильно перегруженного баса столько гармоник, что модель может услышать гармонику как ноту.

Бейджи `!` во вкладке MIDI разбирают, что делать с результатом в FL Studio, по семействам
инструментов.

## Из командной строки

```powershell
conda run -n ai-music-muscriptor python adapters\muscriptor_cli.py --mode probe --upstream ..\muscriptor --json-output artifacts\muscriptor-probe.json
```

```powershell
conda run -n ai-music-muscriptor python adapters\muscriptor_cli.py --mode download --model small --json-output artifacts\muscriptor-download.json
```

```powershell
conda run -n ai-music-muscriptor python adapters\muscriptor_cli.py --mode transcribe --model small --audio artifacts\stem-drums.wav --midi-output output\midi\smoke.mid --json-output artifacts\muscriptor-smoke.json
```

Перед этим задайте `HF_HOME` в `models\muscriptor-cache` и `HF_TOKEN` — своим токеном: флага
`--token` у адаптера нет по замыслу. Прогресс пишется в stdout по одному JSON-объекту на строку,
человекочитаемые логи — в stderr.

## Обновление muscriptor

В отличие от двух детекторов, muscriptor следит за своей веткой и может быть перемотан вперёд из
настроек. Обновление отказывается работать на грязной рабочей копии, на detached HEAD и на всём,
что не является git-репозиторием, а `pull --ff-only` — единственная мутирующая git-команда,
которую приложение вообще выполняет.

Если pull затронул `pyproject.toml`, результат об этом скажет: editable-установка подхватывает
новый код бесплатно, а новые зависимости — нет, и среда иначе тихо разъедется.

Изменение апстрима означает, что MIDI до и после не гарантированно совпадёт. Каждая транскрипция
записывает версию, которой сделана.
