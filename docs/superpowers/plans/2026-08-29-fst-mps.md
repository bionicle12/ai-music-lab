# FST on Apple Silicon MPS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the pinned FST detector on the current Apple Silicon Mac with CPU beat preprocessing, bounded MPS inference, sampled memory telemetry, and unchanged Windows/CUDA behavior.

**Architecture:** Add a native ARM FST environment and a pure device-plan boundary in the wrapper. On macOS, preprocess beats on CPU, run Stage-1 in small MPS batches under a 0.75 allocator fraction, release it, then run Stage-2 on MPS; CUDA keeps its existing all-GPU path.

**Tech Stack:** Python 3.11, PyTorch/TorchAudio 2.8, MPS, PyTorch Lightning, Transformers/MERT, Beat This, pytest, Bash, Git.

**Spec:** `docs/superpowers/specs/2026-08-29-fst-mps-design.md`

## Global Constraints

- Work only on branch `codex/macos-bootstrap`; preserve untracked `.DS_Store` files.
- Keep `../FST-AI-Music-Detection` pristine at `b564f8be8b3db6b7810c2aab61f0b4f86f889579`.
- Keep Stage-1 SHA-256 `f9099df5c618a2f92bcd8f4ba48d1c6606f2e4610385b8eea4a03f1a7319629f`.
- Keep Stage-2 SHA-256 `ed133c261c5d367fc6adf53813a5c93b62a59de5bef546cf5899a5c157eba7a0`.
- Preserve CUDA default batch eight and behavior.
- Use macOS default batch two and valid choices `1`, `2`, `4`, `8`, `0`.
- Reject batch zero on MPS before allocating a model.
- Set MPS allocation fraction to `0.75`, approximately 13.3 GiB on this host.
- Do not enable `PYTORCH_ENABLE_MPS_FALLBACK`.
- Do not add a public full-CPU FST mode.
- Every run records device plan, actual batch, fraction, ceiling, and sampled memory.
- Follow strict test-driven development for behavior changes.

- [ ] **Step 4: Implement staged preprocessing and Stage-1 lifecycle**

In `analyze`:

1. Select and validate the device plan before importing checkpoints.
2. Call `get_segments_from_wav(audio, device=plan.beat_device)`.
3. Configure and sample MPS before Stage-1 allocation.
4. Load Stage-1 with `map_location="cpu"`, then move it to the Stage-1 device.
5. Move only each slice to MPS inside the loop rather than the full 48-segment tensor.
6. Sample after checkpoint load and after every slice.
7. Copy logits and embeddings to CPU for telemetry.
8. Retain the small Stage-2 embedding on its target device.
9. Delete Stage-1, segments, and large temporaries; synchronize and empty the MPS cache.

The per-slice transfer is required: otherwise the complete 48 × 240,000 input
tensor occupies MPS before batching has a chance to constrain memory.

- [ ] **Step 5: Implement Stage-2 lifecycle and final cleanup**

Load Stage-2 through CPU, move it to `plan.stage2_device`, preserve fp16, capture
the fusion gate, and call the published inference function. Copy all results
to CPU, sample memory, delete the classifier and MPS embedding, empty the cache,
then add the tracker summary to telemetry.

CUDA follows the same functional path but skips MPS tracking and keeps its
existing Beat This CUDA device.
